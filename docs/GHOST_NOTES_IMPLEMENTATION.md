
# Реализация отображения "призрачных" нот и адаптивного масштабирования

Этот документ описывает все изменения, внесенные в рамках задачи по отображению нот на двух нотоносцах и адаптации этого отображения к смене ориентации экрана.

## 1. Отображение "призрачных" нот

### 1.1. Постановка задачи

Изначально приложение отображало ноты только на одном нотоносце (скрипичном или басовом). Требовалось реализовать функциональность, при которой ноты, находящиеся в пограничной зоне между станами, отображались бы одновременно на обоих: на своем основном стане как обычная нота, а на соседнем — как альтернативная ("призрачная").

### 1.2. Принятое решение

В качестве визуального представления "призрачных" нот был выбран вариант с **отрисовкой их другим цветом (серым)**. Этот подход был выбран после ряда экспериментов, которые показали, что метод `setParenthesis(true)` (для отрисовки нот в скобках) нестабильно работает в используемой версии `WebView` и `VexFlow`.

Логика была реализована следующим образом:

- **`VexflowNoteMapper.kt`**: Этот файл был кардинально переработан. Вместо того чтобы просто конвертировать список нот в один JSON-массив, он теперь выполняет сложную логику:
    1.  Разделяет входящий список нот на `trebleNotes` (для скрипичного ключа) и `bassNotes` (для басового).
    2.  Определяет, какие из этих нот попадают в заданный диапазон `GHOST_NOTE_RANGE` (от C2 до C5).
    3.  Формирует итоговый JSON-объект, содержащий два массива: `treble` и `bass`. В эти массивы помещаются как основные ноты, так и "призрачные".
    4.  "Призрачные" ноты помечаются специальным флагом `{ "ghost": true }`, чтобы JavaScript-код мог их отличить.

- **Единая модель состояния**: `PianoStaffUiState.kt` была упрощена. Вместо двух полей (`trebleNotesJson` и `bassNotesJson`) теперь используется одно — `notesJson`, которое содержит всю структуру для обоих станов.

- **Обновление ViewModel**: `PianoStaffViewModel.kt` был отрефакторен для работы с единым потоком данных. Он больше не разделяет ноты, а целиком передает список в `toVexflowJson`.

- **`vexflow.html`**: JavaScript-код был обновлен, чтобы принимать два массива нот (`treble` и `bass`) и отрисовывать два голоса (`Voice`) на каждом стане: один для обычных нот, другой — для "призрачных". Если у объекта ноты есть флаг `ghost: true`, к ней применяется стиль серого цвета.

### 1.3. Расширение диапазона "призрачных" нот

Изначально диапазон был небольшим. По вашему запросу он был значительно расширен и теперь охватывает **три октавы (C2 - C5)**. Это изменение было внесено в константу `GHOST_NOTE_RANGE` в `VexflowNoteMapper.kt`.

## 2. Адаптивное масштабирование при смене ориентации

### 2.1. Постановка задачи

При повороте устройства в горизонтальный (ландшафтный) режим ноты, особенно с большим количеством добавочных линеек, переставали помещаться на экране или накладывались друг на друга.

### 2.2. Принятое решение

Была реализована система адаптивного масштабирования, которая работает в связке Kotlin-кода и JavaScript.

- **`PianoStaff.kt`**: Этот Composable-компонент был полностью переписан:
    1.  Он определяет текущую ориентацию устройства (`portrait` или `landscape`).
    2.  Используется `LaunchedEffect`, который отслеживает изменение **и** нот (`notesJson`), **и** ориентации (`orientation`). Это гарантирует, что `WebView` получит команду на перерисовку немедленно после поворота экрана, не дожидаясь начала игры.
    3.  При каждом обновлении в `WebView` вызывается JavaScript-функция `drawGrandStaff`, которой передаются ноты и текущая ориентация.
    4.  **Ключевое исправление**: после вызова `evaluateJavascript` немедленно вызывается `webView.invalidate()`. Этот вызов принудительно заставляет `WebView` перерисовать свое содержимое на экране, решая проблему, когда `WebView` обновлял свой внутренний буфер, но не отображал изменения пользователю до следующего "значимого" события.

- **`vexflow.html`**: JavaScript-код теперь принимает аргумент `orientation`.
    1.  В зависимости от этого аргумента выбираются разные наборы настроек: для `portrait` используется полный масштаб (`1.0`), а для `landscape` — уменьшенный (`0.75`).
    2.  Масштаб применяется ко всему контексту отрисовки (`context.scale(scale, scale)`), что обеспечивает пропорциональное уменьшение всего нотного стана.
    3.  Вертикальные отступы между станами (`trebleY`, `bassY`) остаются постоянными, что в сочетании с масштабированием дает предсказуемый и пропорциональный результат, решая проблему наложения нот.

## 3. Исправление проблемы с масштабированием при повороте экрана

### 3.1. Постановка задачи

После предыдущих изменений возникла новая проблема: при повороте экрана `WebView` не сразу применял новый масштаб. Масштабирование происходило только после получения новой ноты с MIDI-устройства, а не сразу после смены ориентации.

### 3.2. Причина проблемы

Проблема заключалась в состоянии гонки: `LaunchedEffect` в `PianoStaff.kt` пытался выполнить JavaScript-код для перерисовки нотного стана до того, как `WebView` успевал полностью перезагрузить свою HTML-страницу после смены конфигурации (поворота экрана). В результате, вызов `evaluateJavascript` либо игнорировался, либо выполнялся в контексте еще не обновленной страницы.

### 3.3. Принятое решение

Для решения этой проблемы `PianoStaff.kt` был снова переработан с фокусом на жизненный цикл `WebView`:

1.  **Отслеживание размера и состояния загрузки**:
    -   Вместо того чтобы реагировать на изменение ориентации из `LocalConfiguration`, компонент теперь отслеживает реальный размер `AndroidView` с помощью модификатора `.onSizeChanged`. Это более надежный способ определить, когда компоновка завершена и размеры `View` финализированы.
    -   Было добавлено новое состояние `isPageLoaded`, которое становится `true` только после того, как `WebView` полностью загрузит HTML-файл.

2.  **Использование `WebViewClient`**:
    -   Для отслеживания состояния загрузки страницы был установлен `WebViewClient`. Его метод `onPageFinished` используется для обновления флага `isPageLoaded`. Это гарантирует, что JavaScript-код будет выполняться только на полностью загруженной и готовой к работе странице.

3.  **Обновленный `LaunchedEffect`**:
    -   Теперь `LaunchedEffect` зависит от трех переменных: `notesJson`, `viewSize` и `isPageLoaded`.
    -   Код внутри эффекта выполняется только при условии, что страница загружена (`isPageLoaded == true`) и `WebView` имеет ненулевой размер (`viewSize != IntSize.Zero`). Это полностью исключает состояние гонки.

4.  **Очистка `WebView` перед отрисовкой**:
    -   В JavaScript-код (`vexflow.html`) была добавлена логика для удаления старого SVG-элемента перед каждой новой отрисовкой. Это предотвращает появление артефактов и наложения старых нот на новые при частых обновлениях.

## 4. Итог

В результате этих изменений приложение теперь обладает следующими возможностями:
- Корректно отображает ноты в широком диапазоне на двух нотоносцах одновременно.
- Использует интуитивно понятное цветовое кодирование для альтернативных нот.
- Автоматически и немедленно адаптирует отображение к смене ориентации экрана, обеспечивая хороший пользовательский опыт на любых устройствах.
